# MqttBridge - Общая синхронизация состояний через MQTT

![MqttBridge Icon](static/MqttBridge.png)

`MqttBridge` синхронизирует изменения свойств объектов osysHome между разными “домами” через MQTT. Модуль публикует локальные изменения в MQTT и (при необходимости) подписывается на входящие сообщения, применяя их обратно к локальным объектам.

## Описание

Модуль связывает внутреннюю модель объектов osysHome с общим MQTT-пространством топиков:

- действие `proxy` — получение событий о смене свойств и публикация в MQTT
- действие `cycle` — периодическое обновление статистики в админке

## Формат MQTT-топиков

Используются два варианта в зависимости от наличия иерархии классов у объекта:

1. Если `class_path` доступен:
   - `{prefix}/{class_path}/{object}/{property}`
2. Если у объекта нет родителей / class path:
   - `{prefix}/{object}/{property}`

Где:

- `prefix` задаётся в настройках модуля (по умолчанию `home1`)
- `class_path` строится по цепочке наследования объекта (классы/подклассы)
- `object` — имя объекта osysHome
- `property` — имя свойства

## Фильтрация на выходе (Outbound)

Публикация в MQTT ограничивается:

- **Blacklist** (имеет приоритет)
- **Whitelist**

Если whitelist не задан, используется “дефолтное разрешение” (с учётом внутренних ограничений модуля).

## Админ-панель

В интерфейсе модуля доступно:

- **Статус подключения к MQTT**
- **Статистика**: Publishes / Inbound updates / Suppressed echoes
- **Просмотр outbound policy**: какие классы/объекты разрешены/запрещены
- **Настройки**:
  - host, port, login, password
  - `topic_prefix`
  - списки whitelist/blacklist
  - переключатель inbound sync

## Actions

- `proxy` — публикация изменений свойств (outbound MQTT)
- `cycle` — периодические обновления статистики в UI

## Требования
