# MqttBridge – Руководство пользователя

![MqttBridge Icon](../static/MqttBridge.png "MqttBridge plugin")

## Назначение

`MqttBridge` — это мост общих состояний между двумя (и более) инстансами osysHome через MQTT.

Модуль:

- публикует изменения свойств объектов во внешние MQTT‑топики по предсказуемому формату;
- принимает входящие MQTT‑сообщения и может применять их к локальным свойствам;
- позволяет точно контролировать, какие классы/объекты выводятся наружу (whitelist/blacklist);
- защищает от бесконечных “пингов” между домами за счёт подавления эхо;
- показывает в админке статус подключения и статистику работы.

---

## Что получает пользователь

После настройки модуль даёт:

| Возможность | Что делает |
| --- | --- |
| Outbound sync | Публикует `changeProperty` в MQTT |
| Inbound sync | Подписывается на MQTT‑топики и вызывает `setProperty` |
| Topic mapping | Использует стабильный формат топиков `{prefix}/...` |
| Фильтрация | Whitelist + blacklist для классов и объектов |
| Защита от петель | Подавляет “эхо”‑обновления, пришедшие из MQTT |
| Живые метрики | Показывает количество publish/inbound/suppressed и кэши |

## Обзор интерфейса

Админ‑страница доступна по адресу:

```text
/admin/MqttBridge
```

Основные блоки:

1. **Верхняя панель**
   - Метка `Uptime`.
   - Кнопка `Settings` (открывает модальное окно настроек).
2. **Ряд статистики**
   - Карточка `MQTT Connection`.
   - `Publishes`.
   - `Inbound updates`.
   - `Suppressed echoes`.
3. **Краткая конфигурация**
   - Префикс топиков, включён ли inbound, хост/порт брокера.
4. **Outbound filter policy**
   - Читабельное представление текущих whitelist/blacklist.
5. **Модальное окно настроек**
   - Все параметры подключения и фильтрации в одном месте.

## Быстрый сценарий: два дома

Типовой кейс — связать две квартиры/дома:

1. На обоих инстансах osysHome:
   - Установите и включите модуль `Mqtt` (для общей работы с MQTT).
   - Включите плагин `MqttBridge`.
2. Решите, какие префиксы использовать:
   - Дом 1: `home1`
   - Дом 2: `home2`
3. Настройте MQTT‑брокер:
   - Хост/порт.
   - Пользователь/пароль.
   - При необходимости ACL, чтобы оба дома могли читать/писать нужные топики.

### Настройка MqttBridge (общая логика)

- Откройте `/admin/MqttBridge`.
- Нажмите `Settings`.
- Заполните:
  - `Host`, `Port`, `Login`, `Password`.
  - `Topic Prefix` (например, `home1` для первого дома).
- При необходимости заполните:
  - `Whitelist Classes` / `Whitelist Objects`, если хотите жёстко ограничить, что публикуется.
  - `Blacklist Classes` / `Blacklist Objects`, чтобы исключить чувствительные сущности.
- Убедитесь, что `Enable inbound sync` включен, если хотите принимать изменения из MQTT.
- Сохраните настройки (`Save & reconnect`).

## Формат топиков (как читать и что подписывать)

В общем случае:

- если у объекта есть иерархия классов (родители), то используется:

```text
{prefix}/{class_path}/{object}/{property}
```

- если у объекта нет родителей / class_path, то:

```text
{prefix}/{object}/{property}
```

Где:

- `prefix` — строка из поля `Topic Prefix` (например, `home1`);
- `class_path` — цепочка родителей объекта, собранная из `parents` (подробнее в технической справке);
- `object` — имя объекта;
- `property` — имя свойства.

## Пример: “Гостевой режим” между домами

Задача: синхронизировать флаг гостевого режима:

- Объект: `SystemMode`
- Свойство: `guest_mode` (bool)

### Шаг 1 — Общая модель

- На обоих инстансах osysHome создайте объект `SystemMode` со свойством `guest_mode`.

### Шаг 2 — Дом 1

1. В `/admin/MqttBridge` для Дома 1:
   - Установите `Topic Prefix` = `home1`.
   - Укажите хост/порт/логин/пароль MQTT.
   - При желании добавьте `SystemMode` в `Whitelist Objects`.
2. Сохраните настройки.

Теперь при изменении `SystemMode.guest_mode` на Доме 1 модуль публикует:

```text
home1/SystemMode/guest_mode
```

(если у объекта нет class_path; иначе будет добавлена часть с классами).

### Шаг 3 — Дом 2

1. В `/admin/MqttBridge` для Дома 2:
   - Установите `Topic Prefix` = `home2`.
   - Настройте MQTT аналогично.
   - Разрешите inbound sync, если хотите принимать обновления.

После этого:

- Дом 1 публикует в `home1/...`, Дом 2 — в `home2/...`.
- Через модуль `Mqtt` или другие правила вы можете связать топики `home1/...` и `home2/...`, либо положиться на внутреннюю логику inbound `MqttBridge` (если выстроен единый именованный формат).

Механизм подавления эхо в `MqttBridge` гарантирует, что изменения, пришедшие из MQTT и записанные в свойство, не будут обратно опубликованы в MQTT повторно.

## Модальное окно настроек

### Подключение к MQTT

| Поле | Описание |
| --- | --- |
| `Host` | Хост или IP MQTT‑брокера. |
| `Port` | Порт MQTT‑брокера (`1883`, `8883` и т.п.). |
| `Login` | Имя пользователя (если требуется). |
| `Password` | Пароль (если требуется). |
| `Topic Prefix` | Префикс логического “дома” (например, `home1`). |

### Фильтры (Whitelist / Blacklist)

Формат: список через запятую или по строкам.

| Поле | Описание |
| --- | --- |
| `Whitelist Classes` | Если не пусто — публикуются только указанные классы. |
| `Whitelist Objects` | Если не пусто — публикуются только перечисленные объекты. |
| `Blacklist Classes` | Классы, которые никогда не публикуются (имеют приоритет). |
| `Blacklist Objects` | Объекты, которые никогда не публикуются (имеют приоритет). |
| `Enable inbound sync` | Включает применение входящих MQTT‑обновлений к свойствам. |

## Как читать статистику

На главной странице:

- **MQTT Connection**
  - Статус: `Connected`, `Connecting…`, `Error`, `Disconnected`.
  - Время подключения.
- **Publishes**
  - Сколько всего сообщений отправлено.
  - Оценка скорости (сообщений в секунду).
  - Количество ошибок publish.
- **Inbound updates**
  - Сколько входящих обновлений применено к свойствам.
  - Оценочная скорость.
  - Ошибки и ошибки `setProperty`.
- **Suppressed echoes**
  - Сколько эхо‑обновлений было подавлено.
  - Размеры внутренних кэшей и наборов whitelist/blacklist.

Карточка **Outbound filter policy**:

- показывает, какие классы/объекты сейчас разрешены/запрещены;
- подчёркивает, что **blacklist всегда важнее whitelist**.
